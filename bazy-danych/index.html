01

Podstawy baz danych

Najważniejsze pojęcia związane z bazami danych, ich podziałem oraz modelami organizacji danych.

Baza danych

Baza danych to uporządkowany zbiór danych z określonej dziedziny tematycznej, zorganizowany w taki sposób, aby możliwy był łatwy dostęp do zapisanych informacji.

Przykład

Baza danych szkoły może zawierać informacje o uczniach, klasach, nauczycielach, przedmiotach i ocenach.

System zarządzania bazą danych

System zarządzania bazą danych to program zarządzający danymi znajdującymi się w bazie i umożliwiający ich przetwarzanie.

SYSTEM BAZ DANYCH = BAZA DANYCH + SYSTEM ZARZĄDZANIA BAZĄ DANYCH

RDBMS

RDBMS (Relational Database Management System) to system zarządzania relacyjną bazą danych.

SQL

SQL (Structured Query Language) to strukturyzowany język zapytań wykorzystywany do pracy z relacyjnymi bazami danych.

Pełna nazwa: Structured Query Language

Bazy relacyjne i nierelacyjne

Bazy danych można podzielić między innymi na relacyjne i nierelacyjne.

SQL
bazy relacyjne
  • wykorzystują język SQL do wykonywania zapytań,
  • przykładem systemu jest MySQL,
  • baza danych zawiera tabele,
  • tabele składają się z kolumn i wierszy,
  • każdy rekord ma określoną strukturę,
  • tabele mogą być ze sobą połączone za pomocą relacji.
NoSQL
bazy nierelacyjne
  • mogą wykorzystywać różne języki,
  • przykładem systemu jest MongoDB,
  • baza danych może zawierać kolekcje,
  • kolekcje zawierają dokumenty,
  • dokumenty w jednej kolekcji nie muszą mieć identycznej struktury,
  • w tym ujęciu nie występują relacje pomiędzy tabelami.

Modele baz danych

Model bazy danych to zbiór zasad opisujących dane, relacje i powiązania pomiędzy danymi, dozwolone operacje oraz ograniczenia nakładane na dane i wykonywane operacje.

01

Model jednorodny

Wszystkie dane są umieszczone w jednej tabeli lub jednym arkuszu.

Model ten pozwala na łatwe i szybkie odczytywanie danych, ale przy większej liczbie informacji dane mogą być trudniejsze do odnalezienia.

Wadą modelu jednorodnego jest duża liczba duplikatów.
Przykład

Lista kontaktów przechowywana w jednym arkuszu, w którym każdy wiersz zawiera nazwisko, miasto, adres i numer telefonu.

Kowalska Anna | Jelenia Góra | ul. Długa 5 | 555 123 456 Nowak Jan | Wrocław | ul. Leśna 8 | 555 987 654
02

Model hierarchiczny

Dane są zorganizowane w postaci drzewa.

Istnieje jeden korzeń, czyli element nadrzędny, oraz elementy podrzędne.

Jeden element nadrzędny może posiadać wiele elementów podrzędnych, ale każdy element podrzędny ma tylko jeden element nadrzędny.

Przykład

Struktura szkoły: szkoła jest elementem nadrzędnym, poniżej znajdują się klasy, administracja i księgowość, a klasy mogą zawierać konkretnych uczniów.

Szkoła
↓
Klasy Administracja Księgowość
↓
1TI 2TA 3TI
03

Model sieciowy

Model sieciowy może przypominać model hierarchiczny, jednak gałęzie jednego drzewa mogą być wspólne z gałęziami innych drzew.

Oznacza to, że jeden element może być powiązany z wieloma innymi elementami.

Przykład

Firma posiada kilka oddziałów, a te same działy, np. magazyn lub dział sprzedaży, mogą być powiązane z kilkoma oddziałami.

Firma
Oddział Łódź Oddział Gdańsk Oddział Radom
Model sieciowy przyczynił się do powstania modelu relacyjnego.
04

Model obiektowy

Model obiektowy wykorzystuje zasadnicze cechy technologii obiektowej oraz baz danych.

Przykład

W bazie mogą być przechowywane obiekty takie jak Samochód, Właściciel czy Silnik, posiadające własne właściwości.

05

Model relacyjny

Informacje są zapisywane w tabelach w postaci wierszy i kolumn.

Tabele tworzą między sobą powiązania nazywane relacjami.

Przykład

Tabela Producent może być połączona z tabelą Podzespół za pomocą identyfikatora producenta.

Producent id_producenta nazwa adres
→
Podzespół id_podzespolu nazwa_podzespolu id_producenta model
06

Model postrelacyjny

Powstał w wyniku rozszerzenia relacyjnego modelu baz danych o elementy umożliwiające opisanie bardziej skomplikowanej rzeczywistości.

Może wykorzystywać między innymi:

  • złożone struktury danych,
  • zagnieżdżone relacje,
  • atrybuty wirtualne,
  • abstrakcyjne typy danych,
  • funkcje rozszerzalne.
Przykład

Rekord może przechowywać bardziej złożoną strukturę, np. dane klienta wraz z zestawem jego adresów lub innymi zagnieżdżonymi informacjami.
